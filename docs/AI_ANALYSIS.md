# AI_ANALYSIS — 수동 실행 분석 엔진

## 최우선 불변식
**파일/폴더 선택, 등록, 스캔, 썸네일 생성, 갤러리 조회, 검색, MCP 조회만으로 AI 분석 작업을 자동 생성하지 않는다.**

분석은 UI에서 `AI 분석` → 대상/모델/전송 범위/비용 검토 → `분석 시작`을 클릭한 경우에만 실행한다. MCP 명령을 통한 분석은 별도 명시적 분석 도구와 동일한 승인 정책이 필요하다.

## 범위와 해석
| 옵션 | 분석 대상 | 재분석 여부 |
|---|---|---|
| 전체 | 현재 지정 범위의 모든 접근 가능한 에셋 | 기존 완료 포함, 새 run 생성 |
| 미분석 | 현재 유효한 성공 결과가 없는 에셋 | 과거 실패/취소 포함 가능 |
| 분석 완료 재분석 | 성공 결과 보유 에셋 | 새 run 생성, 이전 성공 결과 유지 |
| 분석 실패 재시도 | 마지막 실패 항목 | 새 run 생성 |
| 선택한 에셋 | UI에서 선택한 ID 집합 | 성공 여부와 무관하게 지정 에셋 실행 |

각 옵션은 `현재 폴더(하위 포함)`, `현재 라이브러리`, `전체 라이브러리`와 교차 적용한다. 실제 실행 직전 서버에서 대상 수와 예상 비용을 **재계산**하고 예측치가 바뀌면 사용자에게 안내한다.

## 실행 상태 기계
```text
[명시적 시작] → queued → running → completed
                              ├→ failed
                              └→ canceled
```
- 상태 범주는 *작업(Job)*과 *개별 항목(Job Item)* 둘 다 관리.
- 중복 실행 방지: 동일 에셋/프로필에서 이미 진행 중이라면 중복 큐 방지하거나 사유 표시.
- 중지/취소는 가능한 시점에서 완료. 외부 API 요청 중 이미 발생한 비용은 취소해도 환불되지 않을 수 있음.
- 실행 완료 전에도 항목별 성공 결과를 안전하게 커밋하되 불변 분석 이력에 남김.
- 재분석 성공 시 `asset_active_results`를 새 성공 결과로 갱신할 수 있으며, 과거 성공 데이터는 유지.
- 파일 내용이 변경되면 기존 분석 결과는 보존하고 `outdated/stale`로 식별. 재분석 자동 시작 금지.

## 분석 파이프라인
1. 사전 검사: 입력 파일 존재/지원 형식/읽기 권한/선택 모델 기능 지원 확인.
2. 입력 준비: 원본 파일 기반 로컬 메타데이터·이미지·오디오·모델 정보를 추출. 스크립트 실행 금지.
3. 데이터 최소화: 외부 API를 쓰는 경우 필요한 데이터만 전송하고 사전 고지.
4. Provider Adapter 호출: 로컬 또는 활성화된 외부 모델; 공급자별 시간제한·재시도 정책.
5. 구조화된 결과 검사: 설명/스타일/용도/분류/태그·신뢰도(지원 시) 파싱 및 값 검증.
6. 결과 불변 저장, 현재 활성 결과 갱신, 사용자 수정 정보 보존.
7. 검색 텍스트 갱신, 필요 시 선택적 임베딩/검색 인덱스 생성(**분석 명령 범위 안에서만**).
8. 진행 상태 및 에러 코드 UI 갱신, 감사 로그·호출 비용 기록.

## 입력 유형별 전략
- 이미지/스프라이트: 치수, 투명도, 주제/스타일/용도/색 등 비전 분석.
- 3D 모델: 형식/파일 관계를 읽고 가능한 경우 렌더링한 이미지 기반 평가. 직접 실행/임포트하지 않음.
- 오디오: 길이/형식, 모델 기능에 따라 소리의 종류/용도; 전사 가능 여부는 모델별 검사.
- 비지원 포맷: 기술 메타데이터만 유지, 원인 명시; 성공한 AI 분석으로 오인하지 않기.
- **모든 유형을 같은 모델이 처리할 수 있다고 가정하지 않음.**

## 실패 분류
`FILE_MISSING`, `FILE_PERMISSION_DENIED`, `UNSUPPORTED_FORMAT`, `MODEL_UNAVAILABLE`, `MODEL_CAPABILITY_MISMATCH`, `API_TIMEOUT`, `API_RATE_LIMIT`, `BUDGET_EXCEEDED`, `INVALID_MODEL_OUTPUT`, `USER_CANCELED`, `INTERNAL_ERROR` 등.

## 분석 결과의 최소 스키마 (논리 예시)
```json
{
  "asset_id": "asset-uuid",
  "run_id": "run-uuid",
  "provider": "provider-id",
  "model_id": "model-id",
  "description": "이 에셋의 의미 설명",
  "category": "environment",
  "tags": ["forest", "tree", "stylized"],
  "suggested_use": ["Unity 배경 오브젝트"],
  "input_fingerprint": "sha256:...",
  "created_at": "ISO-8601"
}
```
*실제 모델의 지원 필드만 저장하고 임의 추정값은 채우지 않는다.*

## M06 구현 동작
- 분석 창 열기/프로필 조회/대상 미리보기/상태·이력 조회는 분석 작업을 생성하지 않는다. `analysis.start`의 명시 승인·미리보기 토큰·작업 UUID와 분석별 외부/유료 승인을 검증한 뒤에만 Job을 만든다. 원본 stat·모델 프로필·가격 상한이 바뀌면 다시 검토해야 한다.
- 범위와 모드를 교차 적용한다. 현재 검색/태그 필터는 분석 범위를 좁히지 않으며 선택 모드에서는 실제 선택 ID만 사용한다. 선택 200개·범위 1000개 제한, 동시에 승인된 Job은 하나다.
- Python Core 작업 스레드가 별도 SQLite 연결을 사용해 순차 처리한다. 전송 채널은 3초 응답 제한을 유지하고 긴 추론(연결 5초·소켓 대기 180초)은 채널을 점유하지 않는다. 항목별 원자적 성공 저장·측정 진행률·고정 오류와 최근 20개 Job을 조회한다.
- PNG/JPEG만 현재 AI 경로로 지원한다. 20MB·16MP 이하 입력을 최대 512px JPEG로 변환하고 투명 영역을 흰색으로 합성한다. 파일은 등록 범위/링크·리파스·Windows 열린 핸들의 실제 경로로 재검증하며 원본을 수정하지 않는다. 3D/오디오는 기술 정보만 표시하며 AI 추론/3D 렌더를 수행하지 않는다. 미지원·누락·권한·크기·디코드 오류를 구분하며 PNG/JPEG 후보가 0개면 Job을 만들지 않는다.
- 모델 호출 직전 실제 메타데이터 버전/가격을 재검증한다. 실제 읽은 원본 SHA256과 요청 모델/실제 응답 모델·사용량을 기록하며 모델 출력은 제한된 JSON 설명/태그만 허용한다. 응답에 자격 증명이 반사되면 저장을 거부한다. 외부 보고 비용은 공급자 보고 값이며 청구서 금액으로 단정하지 않는다.
- 외부 유료 상한은 확인된 모델 컨텍스트 최대 입력+최대 512 출력 토큰·명시된 이미지/요청 요금을 보수적으로 계산하며 다른 양수 요금/컨텍스트 미확인은 거부한다. 후보 수만큼 Decimal 상한·호출 수를 Job 생성과 같은 트랜잭션에서 예약한다. 실제 추론/사용량은 예약과 다를 수 있으며 취소/실패 예약을 자동 환급하지 않는다.

- M07 실제 검증에서 로컬 qwen3-vl:2b가 `think:false`에도 추론만으로 512토큰을 소진하고 빈 최종 응답(`done_reason:length`)을 반환하는 사례를 확인했다. 로컬 출력 상한은 1024로 조정하고 명시적 분석 스냅샷에 기록한다. 외부 상한/예약은 512로 유지한다. v2 프롬프트는 한 문장 설명·최대 8개 짧은 태그를 요청하며 로컬 JSON 스키마도 길이를 제한한다. 잘린 출력은 `MODEL_OUTPUT_LIMIT`로 실패하며 추론 원문을 결과나 로그에 노출하거나 자동 재시도하지 않는다. [Ollama thinking 제어 문서](https://docs.ollama.com/capabilities/thinking)에 따라 비활성 요청이 모든 모델의 추론 중단을 보장하지 않음을 전제로 한다.
- 취소는 진행 연결을 닫고 후속 항목을 멈춘다. 실제 마감 전에는 취소 요청 상태로 표시한다. Core가 종료되면 자동 재개하지 않고 중단 상태를 조회·명시적으로 취소/정리한다. 재실행은 과거 조건을 새로 검토하고 별도의 시작 승인을 요구하며 자동 재시도나 유료 폴백을 하지 않는다.
- 불변 이력은 최신순 한 항목씩 조회한다. 실패/취소는 이전 성공 활성 포인터와 사용자 태그/설명을 보존한다. 스캔으로 원본 변경을 확인하면 해시를 무효화해 이전 결과의 재확인 필요 상태를 표시하며 자동 재분석하지 않는다.
