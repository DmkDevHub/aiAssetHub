# ASSET_LIBRARY — 로컬 에셋 관리

## 원본 참조 정책
- 폴더 등록은 기본적으로 **원본 위치 참조(in-place)**. 원본 파일을 자동 복사/이동/삭제하지 않는다.
- DB는 원본 절대 경로와 폴더 내부 상대 경로, 파일 메타데이터, 참조 상태를 보관한다.
- 실제 Unity 적용 시에만 사용자가 선택한 대상 프로젝트의 `Assets/` 등 안전한 경로로 복사·임포트한다.
- 에셋 삭제 버튼은 v0.5에서 **라이브러리 등록 해제**와 원본 삭제를 혼동하지 않도록 구분. 원본 영구 삭제 기능은 기본 비목표.

## 폴더 등록 / 스캔
1. 사용자가 폴더 선택 → 해당 경로를 `library_roots`에 등록.
2. 읽기 권한, 중첩 폴더 등록/중복 여부 검사.
3. 지정 폴더 내부를 스캔해 실제 파일 목록과 기본 메타데이터를 기록.
4. 지원 유형(이미지, 오디오, 3D, 텍스처, 기타) 분류.
5. 가능한 파일은 썸네일 생성. **AI 추론/임베딩 호출은 절대 수행하지 않음.**
6. 완료 후 트리와 갤러리에 실제 파일 표시.

## 논리 에셋과 물리 파일
- **Asset:** 사용자가 탐색·분석하는 논리적 단위. v0.5 기본은 파일당 에셋 1개로 시작하되 묶음(텍스처 세트/모델 종속파일)은 확장 가능해야 한다.
- **Asset File:** 원본 파일, 경로, 확장자, 바이트 크기, 수정시각, 선택적 해시.
- 동일 파일/경로가 두 번 등록되어도 UI 중복 표시 정책을 명확히 하고 임의로 데이터를 지우지 않는다.
- 심볼릭 링크, 순환 디렉터리, 권한 차단, 숨김파일, 초대형 폴더에 대한 방침·테스트 마련.

## 재스캔
- 새 파일: 등록.
- 변경 파일: 변경 마커/필요 시 기존 분석 `stale` 표시. **자동 재분석 금지**.
- 없어진 파일: `missing` 상태, 기존 태그·분석 이력 보존.
- 새 위치로 이동한 파일: 경로 재연결 UI 검토(해시와 사용자 확인 기반).
- 사용자가 수정한 태그·설명은 재스캔 결과보다 우선하고 덮어쓰지 않는다.

## 메타데이터 및 미리보기
- 최소 정보: 표시 이름, 상대/절대 경로, 형식, 크기, 수정시각, 존재 여부.
- 이미지: 해상도·미리보기; 오디오: 길이·포맷 가능 시; 3D: 포맷/기초 속성 및 단계적 프리뷰.
- 검증되지 않은 파일 포맷을 임의로 실행/역직렬화하지 않는다.

## 화면 확인 예시
- 빈 라이브러리에서 실제 폴더 등록 → 에셋 20개가 중앙 갤러리에 표시 → 오른쪽 실제 경로/크기 조회 → 앱 재실행 시 유지.
- 이 전체 단계에서 분석 작업 수·외부 API 호출 수가 증가하지 않아야 한다.

## 현재 폴더 선택 구현 범위 (R03-01)

- 데스크톱 라이브러리 패널의 `폴더 선택`은 운영체제 폴더 선택기를 연다. 선택 경로는 `선택한 폴더`로 표시하고 Vue 세션 메모리에만 보관한다. 화면 이동 중 유지하며 앱 재실행 시 초기화한다. `선택 지우기`는 메모리 선택만 지운다.
- 취소·오류는 이전 선택을 유지한다. 중복 클릭/동시 명령은 선택 창을 더 열지 않으며 컴포넌트 해제 후 도착한 결과는 반영하지 않는다. 브라우저에서는 네이티브 버튼을 제공하지 않는다.
- 허용 범위는 로컬 드라이브의 기존 하위 폴더다. UNC/장치 경로·상대 경로/상위 경로 이동·드라이브 루트·매핑된 네트워크 드라이브를 거부한다. canonicalize 후에도 경로·드라이브 유형을 재검사하며 Win32 `GetDriveTypeW`의 이동식/고정/광학/RAM 드라이브만 허용한다.
- 선택 결과로 가짜 라이브러리 ID·트리 항목·에셋 수를 만들지 않는다. 등록/해제 저장은 R03-02, 파일 스캔은 R03-03이다. 선택은 Core·DB·AI·임베딩·유료 모델을 호출하지 않고 원본을 수정하지 않는다. 폴더 접근/종류 metadata만 확인한다.
- 실제 OS 선택 창은 D-019에 따라 열거나 조작하지 않았다. 내부 어댑터/정책·DOM 흐름·격리 폴더 보존만 검증했으며 OS 대화상자·설치본의 시각/실행 동작은 미검증이다.
