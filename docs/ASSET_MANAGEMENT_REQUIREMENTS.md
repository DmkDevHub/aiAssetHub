# AI Asset Hub v0.5 — 에셋 관리 기능 확장 요구사항

## 1. 목적

AI Asset Hub에서 게임 개발용 에셋의 종류, 분류, 그룹, 이름, 제작사, 출처, 기술 정보 등 모든 메타데이터를 체계적으로 관리한다.

AI가 에셋을 자동 분석하여 메타데이터를 생성하고, 사용자는 이를 조회·수정·검색·관리할 수 있어야 한다.

관리된 정보는 향후 MCP를 통해 Unity 등 외부 게임 엔진에서 에셋 검색, 선택, 임포트, 배치에 활용한다.

### 2.2 다차원 분류

에셋마다 다음 분류를 독립적으로 관리한다.

- **유형 분류:** 대분류 → 중분류 → 소분류
- **역할 분류:** 플레이어, 몬스터, NPC, 무기, 아이템, 환경, 카드 등
- **스타일 분류:** Pixel Art, Anime, Cartoon, Realistic, Low Poly 등
- **장르 분류:** Fantasy, Sci-Fi, Modern, Horror 등
- **시점 분류:** Top-Down, Side-View, Isometric, First-Person 등
- **차원 분류:** 2D, 2.5D, 3D
- **엔진 분류:** Unity, Godot, Unreal, Generic

하나의 에셋에 대표 유형 하나와 복수 역할·스타일·태그를 지정할 수 있다.

캐릭터, 환경, UI처럼 기술적 유형과 의미적 분류가 겹치는 경우에는 대표 유형과 탐색용 분류를 구분하여 중복 관리 문제를 방지한다.

분류 체계는 추후 추가·수정할 수 있어야 한다.

## 4. 그룹·패키지 관리

### 4.1 데이터 구조

- **그룹(Group):** 사용자가 자유롭게 구성하는 논리적 분류
- **패키지(Package):** 배포·구매 단위의 에셋 묶음
- **에셋(Asset):** 이름과 메타데이터를 가진 개별 관리 대상
- **파일(File):** 실제 로컬 저장소에 존재하는 물리적 파일

하나의 패키지에 여러 에셋이 포함될 수 있으며, 하나의 에셋은 여러 파일로 구성될 수 있다.

### 4.2 그룹 관리 기능

- 그룹 생성, 수정, 삭제
- 상위·하위 계층형 그룹 구성
- 에셋의 복수 그룹 소속
- 드래그 앤 드롭으로 그룹 이동
- 그룹별 에셋 조회·검색
- 여러 에셋의 그룹 일괄 지정
- 사용자 정의 그룹 관리
- 조건 기반 스마트 그룹 확장 지원

그룹 구성과 실제 로컬 폴더 구조는 독립적으로 관리하며, 그룹을 이동하거나 삭제해도 원본 파일을 이동·삭제하지 않는다.

## 5. 제작사·제작자·출처 관리

제작자, 제작사, 배포사는 별도 관리 대상으로 구성한다.

**제작 정보**
- 이름, 유형(개인/팀/회사)
- 공식 홈페이지
- 제작자·판매자 프로필 URL
- 연락처, 국가, 설명
- 관련 에셋 및 패키지

**출처·구매 정보**
- 다운로드 사이트 및 원본 URL
- 상품명, 상품 페이지
- 무료/유료 여부
- 구매 가격, 구매일, 다운로드일
- 라이선스 정보 및 증빙 파일 참조

동일한 제작자의 에셋은 제작자 정보를 공유하며, 제작자 정보를 수정하면 연결된 에셋 조회에도 반영한다.

## 6. 에셋 관리 기능

### 6.1 기본 관리

- 에셋 이름 및 설명 수정
- 분류·그룹·제작사·출처 수정
- 태그 추가·삭제
- 즐겨찾기 및 평점 지정
- 사용자 메모 관리
- 관련 에셋 연결
- 원본·파생본 관계 관리

### 6.2 검색 및 필터

다음 항목의 개별 검색과 복합 조건 검색을 지원한다.

- 이름, 설명, 태그
- 대·중·소분류
- 그룹, 패키지
- 제작사, 제작자
- 스타일, 장르, 역할
- 파일 형식, 크기, 기술 속성
- 라이선스, 구매 정보
- AI 분석 상태

정렬은 이름, 파일 크기, 등록일, 수정일, 제작사 등으로 제공한다.

### 6.3 일괄 관리

- 복수 에셋의 그룹 지정
- 복수 에셋의 분류 변경
- 제작사·출처 일괄 지정
- 태그 일괄 추가·제거
- 메타데이터 JSON/CSV 내보내기·가져오기
- 파일 해시를 이용한 중복 확인

## 7. AI 분석 연계

### 7.1 자동 추출 정보

파일 형식에 따라 추출 가능한 정보를 수집한다.

- 파일명, 경로, 확장자, 크기
- 이미지 해상도, 투명도
- 3D 모델 정보
- 오디오 재생 시간
- 애니메이션 프레임 정보
- 패키지에 포함된 메타데이터

### 7.2 AI 분석 정보

선택한 AI 모델을 통해 다음 정보를 분석하거나 추천한다.

- 에셋 대·중·소분류
- 게임 내 역할
- 이름 및 설명
- 아트 스타일, 장르
- 관련 태그
- 유사·연관 에셋

### 7.3 데이터 관리 원칙

1. 폴더 등록 시 AI 분석을 자동 시작하지 않는다.
2. AI 분석은 사용자가 **분석 시작** 버튼을 누른 경우에만 실행한다.
3. 분석 범위는 전체 / 미분석 / 분석완료(재분석)를 지원한다.
4. AI 분석 결과와 사용자 수정 정보를 구분한다.
5. 사용자 확정 정보는 AI 재분석으로 임의 덮어쓰지 않는다.
6. 분석 이력, 모델 ID, 프로필, 결과를 저장한다.
7. 제작사·라이선스·출처처럼 확인되지 않은 정보는 추측하여 확정하지 않는다.
8. 기존 로컬 우선 및 사용자 선택형 모델 정책을 유지한다.

## 8. UI 구성

기존 AI Asset Hub v0.5의 다크 테마 대시보드와 3단 레이아웃을 유지한다.

| 영역 | 주요 기능 |
|---|---|
| 좌측 | 실제 폴더 트리, 사용자 그룹, 패키지, 분류 탐색 |
| 중앙 | 썸네일 갤러리, 검색, 필터, 정렬, 복수 선택 |
| 우측 | 에셋 미리보기 및 전체 메타데이터 조회·편집 |

우측 상세 영역은 다음 탭으로 구분한다.

1. 기본 정보
2. 분류·그룹
3. 제작사·출처
4. 라이선스·구매
5. 기술 정보
6. AI 분석 결과
7. 관련 에셋·이력

제작사, 분류, 그룹, 태그는 별도 관리 화면에서 추가·수정·삭제할 수 있도록 구성한다.

## 9. SQLite 데이터베이스

기존 로컬 SQLite를 유지한다.

주요 논리 테이블은 다음과 같다.

| 테이블 | 역할 |
|---|---|
| `assets` | 에셋 기본 정보 |
| `asset_files` | 실제 파일 정보 |
| `asset_groups` | 그룹 계층 구조 |
| `asset_group_members` | 에셋·그룹 연결 |
| `asset_categories` | 분류 체계 |
| `asset_classifications` | 에셋별 분류 연결 |
| `creators` | 제작자·제작사·배포사 |
| `asset_creators` | 에셋·제작 관계 |
| `asset_sources` | 출처 및 구매 기록 |
| `asset_licenses` | 라이선스 정보 |
| `asset_packages` | 패키지 정보 |
| `asset_package_members` | 패키지 구성 에셋 |
| `asset_tags` | 태그 정의 |
| `asset_tag_links` | 에셋·태그 연결 |
| `asset_metadata` | 유형별 확장 메타데이터 |
| `asset_relationships` | 에셋 간 관계 |
| `asset_analysis_history` | AI 분석 이력 |
| `asset_metadata_history` | 메타데이터 변경 이력 |

이는 논리적인 설계 초안이며 기존 데이터베이스 구조와 중복되는 테이블은 통합하여 최종 결정한다.

## 10. Unity MCP 연계

저장된 메타데이터는 자연어 검색과 에셋 활용 기능에서 사용한다.

**활용 예시**
- "픽셀아트 기사 캐릭터를 찾아줘."
- "OO 제작사의 몬스터 에셋을 보여줘."
- "보유한 판타지 무기 중 3D 모델만 검색해 줘."
- "선택한 에셋을 Unity에 임포트해 줘."
- "기사 캐릭터를 현재 씬에 배치해 줘."

MCP는 에셋 검색 결과뿐 아니라 실제 임포트에 필요한 파일 경로, 구성 파일, 기술 정보, 종속 관계 등을 전달할 수 있어야 한다.

## 11. 개발 적용 원칙

- 기존 AI Asset Hub v0.5 기술 스택 유지
- Tauri 2 + Vue 3 + Python Core Engine + SQLite
- 원본 파일 변경 없이 메타데이터 중심 관리
- 기존 Provider Adapter 및 Model Registry 유지
- Unity MCP 우선, 타 엔진 확장 고려
- 기능을 작은 단위로 나눠 ROADMAP.md에 반영
- 구현 → 자동 테스트 → 검토 → 완료 상태 기록
- 완료 시 CHANGELOG.md 기록 및 기존 Git 운영 원칙 준수

## 12. 구현 우선순위

| 단계 | 개발 범위 | 우선순위 |
|---|---|---|
| 1 | 분류 체계 및 DB 모델 설계 | 필수 |

| 3 | 그룹·패키지 관리 | 필수 |

---

**최종 목표:** AI Asset Hub를 단순 에셋 파일 검색기가 아니라, 게임 에셋의 분류·그룹·제작사·출처·기술 속성·AI 분석 결과를 일관되게 관리하고 게임 개발 도구에서 재사용할 수 있는 통합 에셋 관리 시스템으로 확장한다.
