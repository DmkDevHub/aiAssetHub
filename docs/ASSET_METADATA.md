# ASSET_METADATA — 통합 에셋 관리 확장 설계

> D-029 · 2026-10-29 · 사용자 제공 [확장 요구사항 원문](ASSET_MANAGEMENT_REQUIREMENTS.md)을 반영한 설계 기준.
> **M08A 분류·저장 기반 구현 완료.** 현재 구현은 M00~M08 및 M08A이며, 확장 관리 UI·다중 형식 AI는 후속 범위다. 아래 요구사항 전체가 동작한다고 표시하지 않는다. 설계 변경 당시의 미구현 기록과 현재 구현 상태는 구분한다.

## 1. 관리 단위와 식별
- Group: 실제 폴더와 독립적인 사용자 논리 그룹. 부모/자식 계층과 에셋 복수 소속을 허용한다. 그룹 이동/삭제는 관계만 바꾸고 원본/에셋/분석을 삭제하지 않는다. 자기 참조·순환 부모 연결은 거부한다.
- Package: 구매·다운로드·배포 단위. 여러 에셋과 제작·출처·라이선스 참조를 가진다. 별개 패키지에 같은 에셋을 연결할 수 있다.
- Asset: 안정된 UUID로 관리하는 논리 에셋. 표시명 변경은 원본 파일명 변경과 다르다. 여러 파일·내부 구성 요소를 포함할 수 있다.
- File: 등록 루트 안의 실제 파일. 파일별 원본 이름/경로/형식/크기/수정시각/선택적 해시와 존재 상태를 유지한다.
- 구성 요소: 애니메이션 클립·메시·머티리얼·스프라이트 프레임 등 파일 내부의 식별 가능한 항목. 추출한 실제 경로/인덱스와 버전을 기록하고 존재하지 않는 클립 ID를 생성하지 않는다. 별도 Asset으로 승격할 때만 사용자가 확인한 연결을 만든다.
- 현재 파일당 Asset 1개 구조는 초기 수집 기본값으로 보존한다. 기존 UUID/활성 결과를 유지하면서 다중 파일 연결을 추가하며, 이름·인접 폴더·해시만 보고 자동 병합하지 않는다.

| A06 | 오디오 | BGM, 효과음, 음성, 환경음 |
| A07 | UI·UX | 버튼, 패널, HUD, 인벤토리, 메뉴 |

코드는 안정적인 외부 참조이며 중·소분류에는 별도 ID·부모 ID·한글/영문 표시명·별칭·사전 버전·활성 상태를 둔다. 분류는 최대 대/중/소 3단계로 시작하며 하위 항목은 상위에 포함되어 검색된다. 삭제 대신 비활성/대체 연결을 우선하고 과거 분석의 당시 사전 버전을 보존한다. 사용 중 분류의 재지정은 영향 미리보기·명시 적용을 요구한다.

### 중복 없는 다차원 지정
대표 유형은 확인된 값 하나 또는 미분류이며, 탐색용 의미 분류는 복수 지정할 수 있다. 역할·스타일·장르/테마·시점·차원·엔진을 서로 다른 축으로 관리한다.

| 축 | 예시/판정 기준 |
|---|---|
| 역할 | 플레이어, 몬스터, NPC, 무기, 아이템, 환경, 카드 |
| 스타일 | Pixel Art, Anime, Cartoon, Realistic, Low Poly |
| 장르/테마 | Fantasy, Sci-Fi, Modern, Horror; 게임 장르와 혼동하지 않도록 사전 설명 포함 |
| 시점 | Top-Down, Side-View, Isometric, First-Person; 미확인 허용 |
| 차원 | 2D, 2.5D, 3D; 파일 확장자와 별개 |
| 엔진 | Unity, Godot, Unreal, Generic; 호환 주장과 실제 임포트 검증 상태 분리 |
| 보조 의미 | 대상/소재, 행동, 분위기, 환경, 색상 등 자유 태그·구조화 특징 |

예: 단일 기사 메시의 대표 유형 A02와 역할 캐릭터를 연결한다. 캐릭터 구성 세트는 A09, 독립 걷기 클립은 A03, UI 버튼으로 확정한 이미지는 A07로 관리한다. A01 이미지/A02 모델처럼 물리 매체·구성은 별도 기술 필드로 보존한다. A14 패키지 파일 Asset과 구매 단위 Package는 별개이며 contains 관계로 연결한다. 확장자만으로 의미 분류를 확정하거나 같은 에셋을 대분류마다 복제하지 않는다.

## 3. 공통 메타데이터와 우선순위
| 영역 | 저장할 정보 |
|---|---|
| 기본 | UUID, 표시명, 원본 이름, 별칭, 설명, 에셋 버전, 생성/등록/수정시각 |
| 소속 | 대표 유형/탐색 분류, 역할/스타일/장르/시점/차원/엔진, 그룹, 패키지 |
| 제작 | 제작자/제작사/배포사(개인·팀·회사), 브랜드, 역할별 관계 |
| 제작 주체 사전 | 이름, 유형, 홈페이지, 판매자 프로필 URL, 연락처, 국가, 설명, 관련 에셋/패키지 |
| 출처·구매 | 사이트, 원본/다운로드/상품 URL, 상품명, 무료/유료/미확인, 가격과 통화, 구매일/다운로드일 |
| 라이선스 | 명칭, 이용 조건, 출처 표시문, 확인 상태, 증빙 파일 참조, 적용 범위 |
| 기술·호환 | 파일별 확장자/크기/해시/존재, 유형별 기술 속성, 엔진/버전/임포트 검증 근거 |
| 관리 | 즐겨찾기, 평점(미평가/null 또는 1~5), 관리 상태, 메모, 사용자 태그 |
| AI | 실제 모델/프로필/사전·스키마 버전, 입력 지문, 불변 결과/분석일, 근거 및 지원 시 신뢰도 |
| 관계 | 관련 에셋, original_of/variant_of/derived_from, 구성/종속 관계 |

값마다 source(file/parser/ai/user), 상태(관측/제안/사용자 확정/미확인), 근거 참조와 수정 이력을 분리한다. 사용자 확정/수정값을 표시·필터의 우선값으로 사용하고, 파서 관측과 AI 제안을 덮어쓰지 않고 병렬 보존한다. ‘사용자 값 지우기’와 ‘AI 값 다시 적용’을 구분하고 확인 후 변경한다. 신뢰도는 근거/산정 방식이 있을 때만 저장하며 미제공은 null이다. LLM이 만든 숫자를 보정된 확률로 취급하지 않는다.

제작사·가격·라이선스·출처·엔진 호환은 외형으로 확정하지 않는다. 공급된 메타데이터도 출처와 확인 상태를 표시한다. 가격은 부동소수점 대신 금액/통화를 명시하고 무료(0)·미확인(null)을 구분한다. 패키지 기본 정보는 참조로 상속하며 에셋별 예외를 우선한다. 제작 주체 정보 수정은 연결 에셋 조회에 반영하되 구매 당시 기록/라이선스 이력은 소급 변경하지 않는다.

## 4. 유형별 기술 추출과 AI 분석
| 대상 | 비AI 기술 정보 | 명시 분석에서 제안할 내용 |
|---|---|---|
| 이미지/2D/UI | 해상도, 채널, 투명도, 실제 프레임/아틀라스 메타데이터 | 대상, 역할, 스타일, 시점, 색상, 분류, 이름·설명 |
| 텍스처/머티리얼 | 맵·채널 구성, 재질 파라미터, 실제 텍스처 참조 | 표면 소재/패턴/손상, 용도 후보 |
| 3D | 메시/정점/삼각형 수, 단위/경계 크기, UV, 본/LOD, 재질 참조 | 검증된 파생 렌더 기반 외형/역할/스타일; 실측 폴리곤/리그 호환을 추측하지 않음 |
| 오디오 | 길이, 채널, 샘플레이트, 코덱, 산정 근거가 있는 음량/템포 | 소리 원인, BGM/SFX/음성/환경음, 분위기, 모델 지원 시 전사 |
| 애니메이션 | 클립/프레임/트랙, 길이, FPS 근거, 리그/루트 이동, 이벤트 | 걷기/공격 등 동작, 대상/방향/반복 추천; 실제 loop 설정과 AI 추정 구분 |
| VFX/영상 | 포맷별 지속 시간/프레임/의존성/설정 | 효과·장면·동작·분류; 실행 가능한 셰이더/스크립트로 분석하지 않음 |
| 코드/데이터/씬/패키지/폰트 | 선언된 형식/구조/참조/버전/파일 구성 | 지원 모델의 텍스트 분석 제안; 코드·프로젝트 실행/패키지 설치 금지 |

위 표는 목표 범위이며 지원 형식/파서/모델을 구현·검증한 뒤에만 활성화한다. 현재 실제 AI 경로는 PNG/JPEG이며 다른 형식은 성공한 척 표시하지 않는다. 안전한 기술 추출은 스캔/명시 메타데이터 수집 범위에서 가능하지만, 모델 호출·전사·임베딩·비용 작업은 사용자가 검토 후 분석 시작한 범위에서만 생성한다. 기존 전체/미분석/완료/실패/선택 모드와 취소·재검토·비용 한도를 보존한다.

멀티파일/클립의 대상 판정·부분 성공·취소·입력 지문 범위를 명세하고 기술 추출 완료와 의미 분석 완료를 구분한다. 입력 파일·파생 미디어·전사 텍스트·외부 전송·모델 지원을 사전 표시한다. 새 런타임/모델/디코더 도입은 별도 검토하며 자동 설치·다운로드하지 않는다. 사용자 확정값은 재분석으로 덮어쓰지 않고 과거 성공 결과를 보존한다.

## 5. 논리 DB와 기존 구조 통합 (DDL 아님)
| 요구사항 논리 항목 | 기존 구조 재사용/신규 설계 방향 |
|---|---|
| assets / asset_files | 기존 UUID/파일 FK 재사용, 파일 역할/다중 파일/구성 요소 확장 |
| asset_categories / asset_classifications | 신규 버전형 사전·축별 연결, 대표 유형 유일성; 기존 category 문자열의 호환 투영 정책 정의 |
| asset_groups / asset_group_members | 신규 계층·다대다, 순환 방지·멤버십 삭제 정책 |
| asset_packages / asset_package_members | 신규 묶음·다대다 및 배포/구매 기록 연결 |
| creators / asset_creators | 신규 공유 제작 주체·역할별 연결; 패키지 연결도 포함 |
| asset_sources / asset_licenses | 신규 출처/구매/권리/증빙 참조, 패키지/에셋 적용 범위 |
| 원문의 asset_tags / asset_tag_links | **현행 tags가 태그 사전, asset_tags가 연결**. 이름을 바꾸거나 중복 테이블을 만들지 않음 |
| asset_metadata | 기존 asset_observations/asset_user_annotations/analysis_results.features_json과 역할을 나눠 유형별 스키마·검색 가능한 속성 설계 |
| asset_analysis_history | 기존 analysis_jobs/items/runs/results/asset_active_results 재사용. 불변 트리거·활성 성공 결과 보존 |
| asset_relationships | 신규 방향/종류/구성 파일 참조, 파생 관계 순환·자기 연결 방지 |
| asset_metadata_history | 신규 사용자·일괄 변경 이력, 이전/새 값·행위·버전과 보존/개인정보 정책 |
| search_documents / asset_embeddings / audit_events | 기존 검색/벡터 버전 분리·명시 재구축·레드랙션된 감사 재사용 |

실제 테이블·제약·인덱스·추가 스키마는 R08A-04~05에서 확정한다. 기존 001~003 마이그레이션은 수정하지 않는다. 향후 추가 마이그레이션으로 백업→적용→검증하고 실패 시 롤백한다. 과거 AI 결과나 원본을 자동 변환/삭제하지 않는다.

## 6. UI·검색·일괄 관리
- 기존 다크/라이트 테마와 3단 구조 유지. 좌측은 실제 폴더/그룹/패키지/분류를 구분해 탐색하고, 논리 소속 변경을 물리 파일 이동으로 표현하지 않는다.
- 우측 탭: 기본 정보, 분류·그룹, 제작사·출처, 라이선스·구매, 기술 정보, AI 분석 결과, 관련 에셋·이력. 미지원/미확인/AI 제안/사용자 확정과 저장 실패·미저장 초안을 구분한다.
- 제작 주체/분류/그룹/태그 관리 화면에서 생성/수정/비활성·삭제 영향 검토. 태그 사전 삭제와 특정 에셋의 사용자 태그 제거를 구분하고 AI 불변 이력을 보존한다.
- 이름/별칭/설명/태그, 계층 분류, 그룹/패키지, 제작 주체, 역할/스타일/장르/시점/차원/엔진, 파일 형식/크기/기술 범위, 라이선스/구매, 관리/분석 상태를 복합 필터링한다. 같은 축의 선택은 OR, 축 사이는 AND를 기본으로 하며 미확인 값은 별도로 선택한다. 권한·형식/수치 조건은 관련도/페이지 제한 전에 적용한다.
- 정렬: 이름, 크기, 등록일, 수정일, 제작사 및 기존 관련도. 다중 파일 크기는 가용한 고유 구성 파일 합계로 정의하고 누락/집계 불가를 구분한다. 동률은 안정된 UUID로 결정한다.
- 명시적 메타데이터 편집만 FTS 투영을 갱신하고, 임베딩 입력 변경은 stale로 표시한다. 조회/분류 수정으로 임베딩을 자동 생성하지 않는다. 임베딩 입력에는 선택한 공개 의미 필드만 포함하고 연락처/구매 증빙/인증 쿼리 포함 URL을 제외한다.
- 일괄 분류/그룹/제작/출처/태그 변경은 대상·전후 값·충돌 미리보기→명시 적용→원자 저장/부분 실패 정책·변경 이력. 재스캔/재분석 중 사용자 변경의 버전 충돌을 검사한다.
- JSON/CSV는 스키마 버전/실제 ID·참조 검증, 가져오기 크기 한도/미리보기/명시 적용, CSV 수식 주입 방지와 개인정보 제외 기본값을 둔다. 가져오기가 경로 등록·원본 쓰기·AI 호출·외부 URL 접근을 시작하지 않는다.
- 중복은 명시적 해시 계산으로 후보만 제시한다. 같은 해시가 같은 논리 에셋/구매 권리를 의미하지 않으며 자동 삭제·병합하지 않는다.
- 스마트 그룹은 저장한 읽기 조건을 평가하는 후속 확장이다. 평가가 스캔/분석/임베딩을 시작하지 않는다.

## 7. MCP/Unity·보안 경계
기존 5개 읽기 도구의 응답·필터를 버전 호환 방식으로 확장한다. 실제 분류/그룹/패키지/제작 참조, 구성 파일 역할, 기술 정보, 종속/누락 상태를 반환한다. 경로는 매 호출 시 등록 범위·링크/리파스를 재검증하며 민감한 구매/연락/증빙 정보는 기본 제외한다. 라이선스 미확인은 허용으로 해석하지 않는다. 증빙 파일은 명시 등록한 참조만 관리하고 임의 로컬 경로나 URL로 가져오지 않는다.

MCP 조회는 새 분석/질의 임베딩을 만들지 않는다. 자연어 의미 검색은 현재처럼 명시 승인된 별도 실행 흐름을 유지하며, 새 메타데이터는 오프라인 필터/키워드에서도 검색된다. Unity 쓰기는 별도 임포트/배치 계획→사용자 승인→실제 Editor 결과로만 성공 판정한다. 연결된 리소스의 다운로드/압축 해제/스크립트 실행을 암묵적으로 수행하지 않는다. 감사에 연락처·구매 내역·메모·URL 비밀 쿼리·원본 내용을 기록하지 않는다.
