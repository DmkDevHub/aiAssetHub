## D-025 — M05 초기 모델 검사
초기 로컬 어댑터는 Ollama, 외부 카탈로그는 OpenRouter로 한정한다. 공급자 메타데이터의 직접 REST 조회에는 표준 라이브러리를 사용해 새 의존성을 추가하지 않는다. 생성/추론 SDK와 실제 분석 실행은 M06 범위다. 사용자 제공 ID를 보존하며 설치·다운로드·추론·유료 폴백을 암묵적으로 수행하지 않는다.

## D-026 — M06 수동 분석 실행
명시적 Job 생성 후 Python Core의 단일 승인 작업 스레드가 별도 SQLite 연결(WAL·쓰기 트랜잭션)로 처리한다. 비공개 파이프의 3초 응답 제한을 유지하며 느린 모델 호출은 별도 작업에서만 수행한다. Ollama/OpenRouter 공식 네이티브 REST 규격을 표준 HTTP 클라이언트로 직접 호출해 새 SDK 의존성 없이 구현한다. 외부/유료는 작업별 재승인·사전 상한 예약을 요구한다. 메타데이터 버전/가격 변경·원본 stat 변경 시 자동 재시도/폴백 없이 실패한다. 원본은 읽기만 하고 파생 512px JPEG를 사용한다. 실제 기본 로컬 검증은 CPU qwen3-vl:2b, Ollama 설치·다운로드는 2026-10-28 사용자 명시 승인이다.

## D-027 — M07 로컬 임베딩과 버전 재구축
Ollama의 로컬 embedding capability 모델만 명시적으로 설정한다. SQLite 기존 asset_embeddings에 정규화 float32 벡터를 저장하고 모델·차원·메타데이터·텍스트 규격별 공간을 분리한다. 새 의존성/벡터 DB 없이 코사인 및 역순위 합산으로 검색한다. 생성·질의·전체 재구축은 각각 명시 실행하며 재구축은 전체 계산 성공 후 현재 공간/FTS를 원자적으로 교체한다. 기존 공간은 보존하고 자동 정리·자동 임베딩·모델 다운로드·외부/유료 폴백은 제공하지 않는다. 2026-10-29 추가 다운로드·실제 검증 승인으로 EmbeddingGemma 300m·768차원의 한국어 질의 3개 top1을 실제 분석 결과로 확인했다. 제한된 테스트 이미지 결과이며 내부 수학 fixture 및 일반 검색 품질과 구분한다.

## D-028 — M08 읽기 전용 MCP 채널
설계에 명시한 공식 Python MCP SDK 2.3.0 및 전이 의존성을 고정한다. 기존 Core 실행 파일의 `--mcp` 모드를 Host가 별도 stdio Bridge 프로세스로 실행하며, 이 모드는 SQLite/분석 엔진을 열거나 앱을 시작하지 않는다. 실행 중 Core만 127.0.0.1 동적 포트에 읽기 전용 Broker를 열고 별도 스레드의 Core 소유 DB 연결로 처리한다. 세션별 난수 토큰·UUID·PID와 현재 사용자/SYSTEM 전용 보호 DACL의 발견 파일로 인증한다. 기존 Tauri 비공개 파이프와 쓰기 경계를 유지한다. reference Host는 공식 SDK Client의 실제 별도 프로세스 연결로 검증하고 특정 AI 제품의 설정/모델 실행 검증과 구분한다.


## D-029 — 사용자 제공 통합 에셋 관리 요구사항 반영
2026-10-29 첨부 원문을 [ASSET_MANAGEMENT_REQUIREMENTS](ASSET_MANAGEMENT_REQUIREMENTS.md)에 보존하고 [ASSET_METADATA](ASSET_METADATA.md)를 확장 설계 기준으로 추가한다. A01~A14 대표 유형·독립 분류 축, Group/Package/Asset/File·다중 파일, 사용자 확정 우선·공유 제작/출처/권리·이력·검색·다중 형식 수동 분석을 계획한다. 기존 tags/asset_tags와 분석 테이블은 재사용하고 실제 신규 스키마는 R08A-04~05에서 결정한다. ‘자동 분석’은 명시 승인한 작업 내 처리이며 기존 자동 호출 금지를 변경하지 않는다. 기술 스택·Core 단일 쓰기·원본 보존·화면 직접 조작 금지를 유지한다. 기존 완료 이력/작업 ID를 보존하고 초기에는 M08A~H를 M09 전에, M08I를 M10 뒤에 배치했으나 실행 순서는 아래 D-030으로 대체한다. 현재 요청은 요구사항/문서/로드맵 반영으로 수행하며 신규 기능 구현·기존 DB 변환·원본 수정·재분석은 실행하지 않는다.


## D-030 — M08I를 Unity 개발 전에 수행
2026-10-29 사용자 지시로 스마트 그룹·고급 연관 검색 M08I를 M08H 다음, M09 이전으로 이동한다. 실행 순서는 M08A~H→M08I→M09→M10이며 에셋 관리 확장을 마친 뒤 Unity 연동과 릴리스를 진행한다. 기존 작업 ID·범위·체크 상태는 유지한다. 이번 변경은 개발 순서와 관련 문서 정리이며 신규 기능 구현/검증 완료를 의미하지 않는다.


## D-031 — M08A 버전형 분류·메타데이터 저장 기반
asset-types.v1과 asset-facets.v1을 불변 사전/용어로 저장하고 대표 1개/미분류·탐색 복수·독립 축을 분리한다. 가산 v4는 기존 태그·분석 테이블/UUID/원본을 유지한다. 사용자 명시 clear는 빈 값 확정으로 유지해 AI 제안이 자동 부활하지 않으며, 재적용은 특정 실제 claim을 선택해 승인한다. Core 내부 저장만 제공하며 공개 편집 UI/API·다중 형식 실제 분석은 후속 단계다. 사전 비활성은 구버전을 수정하지 않고 새 버전에 기록하며 사용 참조/승인/대체값을 검사한다. PyInstaller는 아직 외부 API에서 참조하지 않는 내부 계약 모듈도 명시 포함하고 번들 목록을 검사한다.

## D-032 — M08F 단계별 지원·명시 실행·출처 정책
새 디코더/런타임 의존성 없이 기존 Pillow와 Python 표준 라이브러리로 검증 가능한 형식만 지원한다. 지원 파서/전송 한도·미확인 경계는 [ANALYSIS_SUPPORT](ANALYSIS_SUPPORT.md)를 실제 계약으로 기록한다. 기술 수집은 별도 명시 버튼/명령이며 모델/임베딩 Job을 만들지 않는다. 오디오 의미 분석은 기존 OpenRouter 어댑터의 검증된 audio 입력과 작업별 원본 전송/비용 승인을 요구하고 로컬 오디오를 가정하지 않는다. 3D/애니메이션은 안전한 제한 파생 이미지만 모델로 보내며 표면/포즈/호환을 관측한 것처럼 저장하지 않는다. 제안은 불변 결과/claim에 보존하고 사용자 분류로 적용할 때 실제 결과 ID·전후 검토·revision·명시 승인을 요구한다. 공개 검색 메타데이터 변경은 기존 벡터를 stale로 보존·제외하며 자동 재생성하지 않는다. 설치 검증의 모의 공급자를 실제 모델 추론과 구분하고 실제 외부/유료 호출은 검증에 사용하지 않는다.

## D-033 — M08G 원자 일괄·공개 교환·명시 해시
일괄 변경과 가져오기는 읽기 전용 전후 검토/실제 대상·참조 버전 토큰/명시 승인 후 전체 원자 적용한다. 기존 편집기는 SAVEPOINT로 합성해 값/이력/감사를 함께 롤백한다. 교환은 metadata-exchange.v1 공개8종 필드·실제 ID/버전으로 한정하고 CSV는 JSON object 셀로 수식 실행을 막는다. 기존16KiB 통신을 유지하며 파일6000 UTF-8바이트/20개, 일괄100개 한도를 명시한다. 명시 해시는 선택한 고유 구성 파일100개/파일당1GiB의 읽기 전용 SHA-256이고 취소/파일 변경/등록 경계를 검사한다. 캐시 조회는 작업을 시작하지 않고 중단 작업은 명시 정리한다. 같은 해시·크기는 후보일 뿐 논리 에셋/권리 동일성·자동 병합/삭제로 해석하지 않는다. [계약](BATCH_METADATA.md)에 실패·개인정보·검증 경계를 기록한다.
