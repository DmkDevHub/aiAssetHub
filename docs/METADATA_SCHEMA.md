# METADATA_SCHEMA — R08A-04 통합 저장 계약

## 현재 구조 보존
현재 asset_files.asset_id는 수집 시 생성한 원래 소유 에셋이다. 이 FK/UUID와 기존 분석/태그/FTS를 바꾸지 않는다. 다중 파일은 별도 asset_file_members에서 논리 에셋과 물리 파일을 연결한다. 기존 수집 파일은 migration 시 자기 에셋의 source 멤버로 연결한다. 스캔·이름·동일 해시만 보고 묶거나 기존 Asset을 병합하지 않는다. 신규 스캔 파일의 자기 에셋 source 연결은 v4 트리거로 동기화한다. 다중 파일 편집 API/UI는 M08B-03 범위다.

그룹/패키지/제작 주체/권리 테이블은 M08C/D에서 별도 추가한다. 기존 tags/asset_tags와 analysis_jobs/items/runs/results/active 포인터를 재사용한다. 과거 category 문자열은 보존하되 새 분류를 추측해 연결하지 않는다. 필드별 JSON 스키마/민감 값 필터와 사용자 편집 UI는 M08B/E/F에 연결한다.

## 내부 구성 식별
asset_composition.component는 실제 파서가 읽은 file UUID·입력 SHA256·종류·상대 내부 locator를 받아 내부 카탈로그 UUID를 결정적으로 만든다. 경로/파일명이나 Unity 성공 ID를 추측하지 않는다. 파일 지문이 달라지면 다른 구성 ID이며 과거 구성은 원본 버전 참조로 보존한다. 활성 파일의 지문과 맞지 않는 구성은 사용 시 stale로 취급한다. 이 계약 자체는 파서를 구현하거나 클립 존재를 증명하지 않는다.

## 영속성·마이그레이션
001~003 SQL을 편집하지 않고 004로 추가한다. 기존 DB backup API·단일 트랜잭션·체크섬·실패 롤백을 유지한다. 기본 사전만 넣고 에셋의 분류/AI 제안/사용자 결정을 자동 생성하지 않는다. 스키마 v3→v4 보존 검사에는 실제 fixture UUID·사용자 태그·불변 성공/실패 이력·활성 결과·FTS 문서/무결성·모델 Job/벡터 수·원본 해시를 포함한다.

Core 내부 저장 서비스만 새 테이블을 쓴다. 아직 Vue/MCP에 임의 JSON 쓰기 API를 열지 않으며 모델·파일 변경·광범위 재분석을 호출하지 않는다. 사용 중 term 비활성은 새 버전에만 기록하고 참조된 과거 버전은 삭제하지 않는다. 전체 정책/사용자 영향 적용 UI는 후속 관리 작업이다.


## R08A-05 구현
SQLite v4의 004_metadata_foundation.sql로 위 9개 테이블과 사전 스냅샷/용어 103개를 추가했다. 기존 001~003 및 에셋/파일/태그/불변 분석/FTS/벡터는 변경하지 않는다. 사전 2개와 코드만 초기화하고 에셋 분류/제안/결정을 자동 생성하지 않는다.

MetadataStore는 Core 내부 전용이다. propose는 실제 에셋·멤버 파일 또는 같은 에셋의 성공 결과 FK를 검증하고, decide는 명시 승인·기대 revision 일치·set/clear/adopt를 한 트랜잭션으로 적용한다. 관측·AI 제안과 사용자 결정이 분리되며 SQL 트리거가 이전/새 결정과 최초 관측 근거를 이력으로 남긴다. classify는 저장된 사전 버전을 로드해 정규화한 대표/탐색/독립 축과 사용자 이력을 함께 저장한다. 일반 JSON 필드 저장은 형식별 UI 편집 API가 아니며 공개 API의 필드 스키마·개인정보/노출 정책은 M08B/E/F에서 연결한다.

retire_facet은 실제 링크의 사용 에셋 수를 조회해 사용 중이면 승인·같은 축의 활성 대체값을 요구한다. 새 불변 사전 버전만 등록하고 구버전 참조를 바꾸지 않는다. 새 버전의 비활성 값은 선택할 수 없으며 새 버전 재지정은 별도 classify 호출이 필요하다. 현재 기본 버전은 v1이며 전역 기본값 전환/사용자 사전 관리 UI는 후속 범위다.

사전 용어는 JSON 스냅샷과 SQL 행이 일치해야 하며 버전/용어/제안/구성/이력의 수정·삭제는 차단한다. 타입과 다른 축 FK 혼합·비활성·대표/탐색 계층 중복을 거부한다. 결정 revision 단조 증가·명시 clear·adopt 실제 값 일치도 DB에서 검증한다. 메타데이터 변경 이력은 값을 보관하는 업무 데이터이며 레드랙션된 감사 로그와 별개다. 이력/제안 테이블을 MCP에 그대로 노출하지 않는다.

구성 요소 테이블은 식별·보존 기반이며 실제 파서/현재 지문과의 신선도 평가·편집·검색 투영은 후속 M08B/E/F다. 현재 앱/MCP의 분류 지정·메타데이터 편집 동작이 추가된 것은 아니다.


## R08B-01 기본 정보 연결
표시명/설명/별칭은 기존 v4의 basic_text 필드 사용자 결정(객체)과 asset_user_annotations 투영을 한 트랜잭션으로 쓴다. 기존 title/description 조회·검색 계약을 유지하며 별칭은 사용자 결정에서만 읽는다. 미편집 기존 주석은 그대로 읽고 첫 저장 시 명시 결정으로 기록한다. 빈 별칭은 빈 배열로 확정하며 제안을 자동 적용하지 않는다. 새 DDL/마이그레이션은 없다. 이력은 로컬 업무 데이터이며 감사에 텍스트를 쓰지 않는다. 한도/구형 호출 호환/충돌은 [API 계약](API_CONTRACTS.md)을 따른다. 위 M08A의 공개 편집 미연결 기록 중 기본 텍스트만 연결했으며 분류·다중 파일·관계·전체 이력 UI와 별칭 검색은 후속 범위다.

## R08B-02 관리 정보
`management` 사용자 결정에 favorite(bool), rating(null 또는 정수 1~5), status(unreviewed/reviewing/approved/archived), notes(1024자), assetVersion(64자), createdDate/modifiedDate(빈 값 또는 실제 YYYY-MM-DD, 생성일≤수정일)를 저장한다. 날짜는 사용자 에셋 정보이며 OS 파일 시각과 독립적이다. 고정 Core/Tauri 명령만 허용하고 revision 비교와 이력을 한 트랜잭션으로 처리한다. v4 저장 기반을 사용하며 새 의존성/DDL/AI 호출은 없다. GUI 배치는 미검증이다.

## R08B-03 구성 참조
`composition` 결정은 files(fileId/role, 최대 16개)와 components(기존 관측 UUID 최대 16개)를 기록한다. asset_file_members 투영·결정·이력이 한 트랜잭션이다. 소유 파일의 source 역할은 제거할 수 없다. 명시 연결만 하며 asset_files.asset_id와 원본은 바꾸지 않는다. 구성 요소는 연결 파일의 현재 해시와 일치하는 기존 관측만 선택 가능하다. 신규 파서/mesh·clip 추출은 M08F이며 수동 문자열을 실제 관측으로 만들지 않는다. 후보는 활성 라이브러리 실제 ID를 2개씩 페이지로 조회한다. 가용성은 마지막 스캔 기준이며 비활성 루트는 사용 불가, 변경된 해시 참조는 stale로 표시한다.

## R08B-04 에셋 관계
`relations` 사용자 결정 배열(최대 16개, targetId/kind)을 사용한다. related는 의미상 대칭이며 양쪽에서 송신/수신 조회할 수 있으나 중복 행을 만들지 않는다. original_of는 현재→변형/파생 대상, variant_of/derived_from은 현재→원본/부모 방향이다. 쓰기 잠금 안에서 모든 에셋의 결정 그래프를 자식→부모 방향으로 정규화하고 Kahn 알고리즘으로 순환을 검사한다. 자기 연결·중복·미등록/비활성 대상과 순환은 결정/이력 모두 롤백한다. 조회는 원본을 바꾸지 않고 비활성 대상도 사용 불가로 보존한다. 대상/수신 조회는 고정 명령에서 실제 UUID 기준 2개씩 페이지 처리한다.
## R08B-05 변경 이력과 충돌

기존 append-only metadata_decision_history 트리거를 사용해 기본 텍스트·관리 정보·파일 구성·관계·사용자 태그의 사용자 확정 행위, 필드별 버전, 이전/새 값과 시간을 저장한다. 새로운 스키마나 의존성을 추가하지 않는다. 이력 이전의 레거시 데이터는 과거 값을 추측해 재작성하지 않는다.

UI는 읽은 revision으로 저장하며 충돌 시 초안을 유지하고 재저장을 막는다. 에셋 선택 변경/컴포넌트 해제 후 늦게 도착한 응답은 버린다. 레거시 명령과 태그 일괄 add/remove 호환 동작은 API_CONTRACTS.md를 따른다. 읽기 실패 시 빈 값 저장을 허용하지 않는다.

이력은 1개씩 실제 ID 커서로 조회한다. 전달 한도를 넘는 값은 truncated/preview로 명시하고 DB 원문은 유지한다. 이력 열람/저장 시 로그에 사용자 메모·파일 경로·토큰·원시 예외를 출력하지 않는다. 실패한 저장은 투영·결정·이력을 함께 롤백한다. 재스캔 및 새 분석 후보는 사용자 결정과 이전 활성 성공 결과를 덮어쓰지 않는다. 실제 분석 모델 호출 없이 성공/실패 이력 fixture와 신규 후보를 사용해 검증한다.

## M08C / R08C-01
005_collections.sql(v5)은 asset_groups, asset_group_members, asset_collection_versions, append-only collection_history를 추가한다. 기존 001~004는 변경하지 않는다. 그룹(name 128자·description 512자)은 실제 폴더/Asset/File/분석과 독립적이다. 소속은 실제 활성 에셋/그룹만 최대 32개, 에셋별 group revision으로 원자 교체한다. 그룹 삭제는 연결만 해제하고 영향 에셋의 소속 버전·이력을 갱신한다(비활성 루트의 기존 소속도 포함). 부모 이동은 R08C-02에서 활성화한다. 고정 Core asset.groups.* 및 Tauri group_* 명령만 제공하며 모델/스캔은 호출하지 않는다.

### R08C-02~03
부모 변경은 실제 ID와 조상 체인을 쓰기 잠금에서 검증하며 자기/순환을 거부한다. 부모 삭제 시 자식은 최상위로 승격하고 버전/이력을 남긴다. DND와 키보드 모두 검토 후 명시 적용하며 취소/실패 시 계층이 바뀌지 않는다. 그룹별 검색은 키워드/태그/파일 형식/폴더/분석 상태를 모두 평가한 후 200개 UUID 커서 페이지를 적용한다. 의미/혼합 검색에도 group_id 필터가 랭킹 전에 적용된다. 일괄 지정은 최대 100개 실제 에셋과 8개씩 추가/해제 그룹을 검토하고 before/after를 2개씩 페이지로 반환한다. 적용은 에셋 소속 버전과 그룹 버전 전체 일치를 검사하여 원자 저장한다. 한 에셋은 32개 그룹까지 소속하며 응답 이름은 64자로 줄이고 ID를 유지해 16KiB 전달 한도를 지킨다.

### R08C-04 패키지
006_packages.sql(v6)은 asset_packages, asset_package_members, package_purchase_snapshots를 추가한다. 패키지는 배포/구매 단위이며 물리 폴더·논리 그룹·A14 파일 에셋과 별개다. 명시적으로 선택한 실제 에셋이 여러 패키지(최대 16개)에 속하며 패키지도 여러 에셋을 포함한다. 금액은 null(미확인) 또는 음수가 아닌 12자리 정수/최대 소수 4자리 문자열이며 숫자 부동소수점은 거부한다. 금액 지정 시 대문자 3자리 통화가 필수다. 날짜는 실제 YYYY-MM-DD다. 최초 소속 시 패키지명 요약·구매 기록/시간을 불변 스냅샷으로 남겨 수정/소속 해제/재연결 시 소급 변경하지 않는다. 삭제는 패키지 비활성·연결 해제/버전/이력만 수행하며 보관 행과 구매 당시 기록·원본/분석은 유지한다. 새 구매 이력/제작 주체/권리 참조 확장은 M08D 범위다.
### R08C-05 패키지 상속과 예외

패키지의 공유 기본값은 engine(128자), sourceUrl(512자 HTTPS·자격 증명 금지·자동 가져오기 없음), licenseLabel(256자 선언명)이다. 패키지 버전은 assetVersion 상속 후보가 된다. 이 값은 엔진 호환성 또는 이용 권한 검증 결과를 의미하지 않는다. 제작 주체/라이선스 객체·증빙 참조는 M08D에서 확장한다.

에셋 조회 시 현재 소속 패키지의 기본값을 참조한다. 값이 같으면 근거 packageIds를 함께 반환하고, 서로 다르면 값 선택 없이 conflict로 반환한다. 데이터 복사나 첫 번째 패키지에 따른 임의 우선순위를 사용하지 않는다. 기본 메타데이터 관리에서 확정한 에셋 버전은 패키지 버전보다 우선한다. 미확정 AI 버전은 사용자 확정으로 취급하지 않는다.

engine/sourceUrl/licenseLabel의 개별 예외는 기존 metadata_decisions의 package_overrides 필드에 저장한다. 키 없음은 상속, 문자열은 개별 값, null은 상속을 막는 명시적 미확인이다. 예외 전체를 빈 객체로 저장하면 상속을 다시 적용한다. 저장은 예외 revision과 실제 소속 packageVersions 전체를 비교하며 충돌 시 초안/기존 결정/이력을 보존한다. 구매 당시 스냅샷과 원본/분석은 변경하지 않는다. 공유 정보가 갱신되어도 편집 중인 초안은 자동 폐기하지 않는다.
