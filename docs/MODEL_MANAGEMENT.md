# MODEL_MANAGEMENT — 모델 카탈로그·공급자·비용

## 구조
- `Model Registry`: 모델 이름/ID, 공급업체, 버전, 입력 양식(이미지·텍스트·오디오 등), 기능, 비용/제약, 사용 상태.
- `Provider Adapter`: 서로 다른 공급자 SDK 호출 방식, 타임아웃, 응답 파싱, 사용량 보고 등을 공통 결과로 통일.
- `Native SDK`: 각 공급자의 공식 라이브러리 직접 사용(이 프로젝트에서 LangChain/LangGraph 도입하지 않음).
- 새 모델이 나와도 가능한 한 모델 목록/설정 갱신으로 대응하고, 호출 규격이 달라질 때만 어댑터 수정.

## 화면 사용자 흐름
1. 모델 관리 화면에서 **로컬 모델** 목록/구동 상태/필요 자원 확인.
2. 외부 모델은 공급자 선택 후 API 자격 증명 저장 및 연결 테스트.
3. 유료 공급자는 기본 OFF; 사용자 활성화 및 사용 한도 설정 후 허용.
4. AI 분석 다이얼로그에서 해당 에셋의 유형을 지원하는 모델만 선택 가능.
5. 실행 전 대상 수·예상 요금·전송 데이터·잔여 한도를 보여줌.

## 비용 정책
- **무료 외부 모델에도 호출 한도·데이터 전송이 있으므로 로컬 모델과 구분**.
- 실제 가격과 토큰/호출량은 공급자 변경 가능하므로 고정 상수가 아닌 설정/메타데이터로 관리.
- 사용자가 지정한 예산 하드리밋을 넘길 가능성이 있으면 시작 거부/호출 전 중지.
- 예상 비용은 추정치임을 표시하고 실제 사용량·실제 청구 차이를 기록.
- `외부 전송 허용` 및 `유료 모델 사용 승인`을 암묵적으로 활성화하지 않는다.

## 재현성과 호환성
- 매 run마다 provider, model ID, 버전/프로필, 프롬프트 스키마 버전, 모델 설정, 입력 해시를 스냅샷으로 저장.
- 임베딩 모델 변경 시 기존 벡터와 무조건 혼합하지 않고 버전별 재색인 관리.
- 로컬 모델이 실행 불가능하면 임의로 유료 모델로 폴백하지 않는다.
- API 키/비밀은 OS 보안 저장소에 보관하고 DB/로그/문서에 평문 저장하지 않는다.

## 미확정 구현 선택
- 초기 로컬 모델 런타임과 기본 제공 모델은 실제 PC 사양과 포맷 지원에 따라 결정.
- 외부 공급자별 인증 방식·지원 모델·요금은 구현 직전 공식 문서에서 재검증.

## M05 초기 어댑터
로컬 Ollama 메타데이터 `POST http://127.0.0.1:11434/api/show`만 명시적으로 검사한다. 생성/모델 로드/다운로드 호출은 하지 않으며 등록 입력과 실제 capabilities를 구분한다. 고정 URL·환경 프록시 배제·리다이렉트 거부·0.5초 소켓/1.5초 총 읽기 제한·2MB 응답 제한을 적용한다. 상태 확인은 모델 추론 성공을 보증하지 않는다. [Ollama 공식 API](https://docs.ollama.com/api/introduction), [메타데이터 문서](https://docs.ollama.com/api-reference/show-model-details). 메타데이터 조회에는 기존 Python 표준 HTTP 라이브러리를 사용하며 생성 SDK 선택은 실제 추론 구현 단계에 결정한다.

## 외부 메타데이터 검사
OpenRouter의 고정 `GET https://openrouter.ai/api/v1/models` 카탈로그에서 입력한 정확한 모델 ID를 찾는다. 외부 전송 동의가 필요한 별도 버튼이며 에셋/프롬프트/생성 요청은 보내지 않는다. [공식 모델 API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)의 입력 유형·pricing을 검사하고 모든 명시된 가격이 0인 경우만 무료로 판정한다. 키 없는 카탈로그 조회는 authentication=not_tested로 표시한다. 메타데이터 요청 시도와 추론 호출 여부를 구분하며 네트워크 실패를 숨기지 않는다.
