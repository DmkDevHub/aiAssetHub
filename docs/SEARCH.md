# SEARCH — 에셋 검색 및 의미 검색

## 검색 모드
1. **기본 검색:** 파일명, 폴더, 확장자, 카테고리, 사용자가 지정한 태그·설명.
2. **분석 정보 검색:** AI가 생성한 설명, 태그, 용도, 스타일 및 기타 구조화된 필드.
3. **자연어 의미 검색:** 텍스트 임베딩 등 의미 유사도 기반, 실제로 벡터가 준비된 대상만 포함.
4. **혼합 검색:** 키워드 + 메타데이터 필터 + 의미 유사도 점수를 결합.

## 구현 순서
- 첫 단계: SQL 기반 필터 + SQLite FTS5 전문 검색 인덱스.
- 한국어 검색 품질은 FTS5 기본 토큰화만 믿지 않고 띄어쓰기·한글 형태·부분 문자열 검색을 테스트하고 필요한 보정 설계.
- 이후 선택 모델로 임베딩 생성 및 저장; 전체 로컬 크기에 따른 성능 검증 후 단순 비교 vs 전용 벡터 확장 결정.
- AI 분석이 없는 파일도 파일명/사용자 태그로 검색되어야 한다.
- 외부 검색 API 또는 외부 Vector DB를 필수로 만들지 않는다.

## 검색 데이터 동기화
- 사용자 태그/설명 수정 시 인덱스 갱신.
- 분석 성공·활성 결과 변경 시 AI 텍스트 인덱스 갱신.
- 파일 변경 시 과거 결과와 인덱스의 버전 표시 및 재색인 계획 기록.
- 기존 검색 인덱스는 분석 결과와 사용자 메타데이터에서 재구축 가능해야 한다.
- **검색어 입력만으로 외부 AI 호출·AI 분석·임베딩 생성이 시작되지 않음.** 의미 검색용 질의 임베딩 요청은 사용자가 해당 검색 모드를 선택하고 모델 설정/동의한 경우에 한정; 외부 호출 고지.

## 정렬·결과 설명
- 이름, 수정일, 타입, 분석일, 관련도 정렬.
- 관련도는 기본 키워드 점수와 의미 점수를 구분해 계산하고 검색 모드에 따라 조합.
- 필터는 분석 여부, 형식, 폴더, 태그, 원본 파일 존재 여부 등을 지원.
- 결과 카드 클릭 시 오른쪽 상세 패널에서 이유/태그/활성 분석 출처를 확인 가능.

## 합격 기준
- 분석 전 이미지도 파일명 검색됨.
- 분석 완료 후 “숲에서 쓸 만한 나무” 자연어 검색 시 준비된 샘플에서 적합 에셋이 노출됨.
- 한글 파일명·한글 태그·복수 공백·대소문자·부분 단어를 포함한 테스트 데이터셋 통과.
- API 호출 금지 상태에서 기본 검색이 오프라인 동작.

## M04 구현 범위 (R04-05)
- DB v2의 `asset_fts`(FTS5 unicode61, 외부 content `search_documents`)와 파생 뷰/트리거 사용. 파일명·상대 경로·표시명·사용자 설명/태그 및 현재 활성 분석의 설명/태그를 NFKC·casefold·공백 정규화해 색인한다. 과거 비활성 AI 태그는 제외한다.
- 입력은 최대 256자/16단어. 모든 단어를 FTS 리터럴 prefix로 인용해 AND 검색하고, 한글 부분 단어·1~2자 검색은 문서 문자열 AND 일치로 보완한다. 검색은 오프라인이며 모델/임베딩/작업을 생성하지 않는다.
- 등록 활성 폴더의 ID만 200개씩 반환한다. 입력 즉시 파일명/태그 결과를 표시하고 Core 응답으로 설명까지 포함한다. 오래된 응답/페이지는 버리며 실패 시 제한된 대체 검색임을 알린다.
- DB 업그레이드 시 백업 후 기존 메타데이터를 색인한다. SQL 트리거로 스캔/사용자 정보/태그/활성 결과 변경을 같은 트랜잭션에서 반영하고 문서 version을 증가시킨다. FTS는 `INSERT INTO asset_fts(asset_fts) VALUES ('rebuild')`로 파생 문서에서 재구축 가능하며, 문서 자체는 `asset_search_source`에서 재구축 가능하다. 별도 사용자 재구축 명령은 아직 제공하지 않는다.
- 자연어 의미 검색/관련도 랭킹·임베딩·형태소 분석은 후속 범위다. 대규모 한글 부분 문자열 검색의 성능은 미검증.

## M04 복합 필터·정렬 (R04-06)
- 검색 결과에 폴더/하위 폴더·사용자 태그·타입·분석 상태를 AND로 적용한다. 필터는 전체 인덱스에서 선택하며 60개 표시 페이지를 나누기 전에 적용한다.
- 완료는 활성 성공 결과 보유, 미분석은 활성 성공 결과 없음, 실패는 마지막 analysis_run의 실패다. 완료와 실패는 겹칠 수 있다. 실제 분석 실행 기능은 M06 범위이며 M04는 DB에 존재하는 결과/시도만 조회한다.
- 기본 ID순/이름순/타입순/파일 수정일 최신순/활성 결과 분석일 최신순을 지원한다. 나노초 수정일은 문자열로 운반하고 BigInt로 비교하며 동률은 이름·ID로 결정한다. 분석일 없는 항목은 뒤에 표시한다.

## M07 구현: 명시적 로컬 의미 검색
- 라이브러리의 ‘의미 검색 준비’에서 이미 설치된 Ollama 임베딩 모델 ID와 텍스트 규격을 명시적으로 확인·저장한다. `/api/show`의 embedding capability·차원을 확인한다. 앱은 모델을 설치·다운로드하지 않으며 외부/유료 임베딩을 지원하지 않는다.
- 모델 ID·메타데이터 SHA256·차원·입력 규격·포맷 버전으로 벡터 공간을 구분한다. 선택한 현재 성공 결과(한 번에 최대 100개)의 AI 설명/태그만 ‘선택 결과 임베딩 생성’으로 전송한다. 스캔·목록·상태 조회는 모델을 호출하지 않는다. 활성 결과/원본 해시/벡터 공간이 다른 데이터는 준비 수와 검색에서 제외한다.
- 기본 키워드 검색은 오프라인이다. 의미/혼합 모드를 선택하고 ‘로컬 검색 실행’을 눌러야 질의 임베딩을 생성한다. 질의는 작업 중 메모리에만 유지하며 DB 작업 기록에는 원문을 저장하지 않는다. 검색/생성은 별도 스레드에서 처리하고 Core 재시작 후 자동 재개하지 않는다.
- 의미 검색은 L2 정규화 벡터의 코사인 내림차순이다. 혼합은 키워드 문자열 일치 밀도 순위와 의미 순위에 `1/(60+rank)`를 합산한다. 사용자 태그·폴더·타입·분석 상태를 제한 전에 적용하고 최대 50개를 반환한다. 동률은 실제 에셋 UUID로 결정하며 점수는 확률이 아니다. 벡터가 없는 혼합 검색은 키워드 결과만 표시하며 모델을 호출하지 않는다.
- 준비 상태 확인 후 전체 재구축 체크박스를 승인하고 실행한다. 현재 활성 결과 최대 1000개의 벡터를 계산한 뒤 결과/원본/모델 버전을 재검증하고, 현재 공간의 벡터와 키워드 문서/FTS를 하나의 트랜잭션으로 교체한다. 실패 시 기존 인덱스를 보존하며 다른 공간의 벡터는 삭제하지 않는다. 후보 조회는 최대 10000개이며 초과 시 명시적으로 실패한다. 대규모 성능은 미검증이다.
- EmbeddingGemma 입력 규격은 문서 `title: none | text: `, 질의 `task: search result | query: `를 사용한다. 일반 규격은 접두어를 추가하지 않는다. 실제 모델에 맞는 규격은 사용자가 선택하며 규격 변경도 새 공간이다.
- 근거: [Ollama Embed API](https://docs.ollama.com/api/embed), [Google EmbeddingGemma 300m 모델 카드](https://huggingface.co/google/embeddinggemma-300m). 실제 모델 품질 검증은 별도 승인된 로컬 실행으로만 기록한다. 내부 수학 fixture 통과를 한국어 검색 품질 실측으로 간주하지 않는다.


## D-029 메타데이터 검색 확장 목표 (미구현)
별칭·분류 계층·그룹/패키지·제작 주체·역할/스타일/장르/시점/차원/엔진·파일 크기/기술 범위·라이선스/구매·관리/분석 상태를 검색/복합 필터에 추가한다. 같은 축 OR/축 사이 AND, 미확인 값 별도 선택·하위 분류 포함을 기본으로 하고 페이지/관련도 제한 전에 적용한다. 이름/크기/등록일/수정일/제작사 정렬을 확장한다. FTS는 확정 메타데이터 갱신에 동기화하지만 임베딩은 stale 표시 후 명시 재생성한다. 구매/연락/증빙은 의미 입력에서 기본 제외한다. 현재 MCP 키워드 전용·조회 모델 호출 0건 경계를 유지하며 [통합 설계](ASSET_METADATA.md) M08E/H를 따른다.
